# Study Diagrams

1. Choose the diagram type from the relationship: flowchart for decisions,
   sequence for events, tree for hierarchy, and component diagram for architecture.
2. Include only nodes needed to explain the question.
3. Use consistent direction, names, shapes, and arrow meanings.
4. Label decisions and important data passed between steps.
5. Avoid crossed lines and decorative elements that obscure the structure.
6. Compare the diagram with the source code or assignment before delivery.
7. Provide a short textual explanation so the diagram is understandable and accessible.

Never imply a runtime connection or dependency that the source does not establish.
