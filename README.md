# Лабораторные работы 1С Фактория

В репозитории находятся учебные конфигурации для платформы «1С:Предприятие».

## Подробные описания всех лабораторных

Каждая страница содержит цель, задания, объекты конфигурации, порядок действий,
объяснение реализации, сценарий защиты и проверку результата.

| Работа | Полное описание |
| --- | --- |
| 1 | [Справочники, константы, перечисления и подсистемы](docs/Lab1.md) |
| 2 | [Встроенный язык, строки, условия и коллекции](docs/Lab2.md) |
| 3 | [Документы, формы, суммы строк и итоги](docs/Lab3.md) |
| 4 | [Ввод на основании и производство продукции](docs/Lab4.md) |
| 5 | [Регистр продаж и проведение документов](docs/Lab5.md) |
| 6 | [Отчёт по продажам на СКД](docs/Lab6.md) |

Начните с [инструкции по загрузке и подготовке базы](docs/START.md).
В методичке на обложке указаны работы 1–7, но отдельного задания №7 в приложенном
документе нет. Здесь описаны шесть фактически присутствующих работ.

## Файлы

- `Lab1.cf` — архивная копия исходного `1Cv8.cf`; название историческое, файл уже содержит объекты последующих работ.
- `Lab2-progress.cf` — архивная копия `1Cv8_2.cf`, промежуточный снимок работы над лабораторной №3.
- `Lab3-final.cf` — итоговая конфигурация после третьей лабораторной работы.
- `source/` — текстовые выгрузки архивных и итоговых конфигураций, включая работы 4–6, для просмотра кода и истории изменений через Git.
- `metadata/Фактория.xml` — описание подсистемы «Фактория».
- `TASKS.md` — формулировки заданий лабораторных №2 и №3.
- `DEMO.md` — порядок запуска и демонстрации лабораторной №3.
- `VALIDATION.md` — результаты автоматической проверки итоговой конфигурации.

## Лабораторная работа 2

Реализованы задания на встроенном языке 1С: сокращение ФИО, расчёт розничной цены, условная логика, работа с массивом и таблицей значений.

## Лабораторная работа 3

Созданы справочники поставщиков и договоров, документы «Заказ поставщику», «Приходная накладная» и «Расходная накладная». Настроены табличные части, отбор номенклатуры, автоматический расчёт сумм и итоги в подвалах таблиц.

Итоговая конфигурация `Lab3-final.cf` проверена средствами конфигуратора 1С: ошибки проверки не обнаружены, структура тестовой базы обновляется успешно.

## Открытие конфигурации

В Конфигураторе выберите **Конфигурация → Загрузить конфигурацию из файла** и укажите нужный файл `.cf`. После загрузки выполните **Конфигурация → Обновить конфигурацию базы данных**.

## Лабораторные 4–6

Готовы отдельные последовательные версии: `Lab4.cf`, `Lab5.cf`, `Lab6.cf`.
Для всех изменений сразу используйте **Lab6.cf**. Перед загрузкой сохраните
резервную копию учебной базы через «Администрирование → Выгрузить информационную базу».
CF содержит структуру и код, но не введённые пользователем данные.

- №4: заполнение приходной накладной из заказа, документ производства, фиксированный массив видов материалов.
- №5: оборотный регистр продаж, движения товаров и услуг, перепроведение и отмена проведения.
- №6: отчёт СКД по продажам с периодом, необязательным отбором номенклатуры, группировкой по контрагентам и итогами.

Подробные действия через интерфейс: [ИНСТРУКЦИЯ_ЛР4–6.txt](ИНСТРУКЦИЯ_ЛР4–6.txt).
Методичка сохранена в `materials/Методичка.docx`. Исходники — `source/Lab4`,
`source/Lab5`, `source/Lab6`. Код автоматических сценариев — `tests/LabTests.bsl`;
он запускается только во временной тестовой конфигурации и не входит в CF.
Результаты проверок платформы и сценариев от 26 октября 2026 года — `validation/`.

Проверены перенос данных, фильтр из двух видов, дробное количество производства,
запись продаж, количество услуги 1, отсутствие дублей, отмена проведения,
выполнение СКД и сумма выбранного товара 200 в сформированном отчёте.
Нативный интерфейс вручную не проверялся. Учебная лицензия запрещает экспорт
табличного документа; результат отчёта проверен в памяти.

На рисунке методички присутствует Контрагент, хотя таблица измерений перечисляет
только Номенклатуру. Поэтому в регистр добавлен Контрагент, заполняемый существующим
реквизитом Поставщик расходной накладной. Оформление отчёта — «Море».

Генераторы в `scripts/build_*.py` использовались для подготовки исходников.
Для обычного запуска нужны только готовые CF; повторный запуск генераторов
не требуется и может перезаписать изменения исходников.
