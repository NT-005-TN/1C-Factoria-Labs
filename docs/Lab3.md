# Лабораторная 3 — документы и программирование форм

[Все работы](../README.md) · [Запуск базы](START.md) · [Следующая работа](Lab4.md)

Пошаговое повторение с промежуточными действиями: [каждый шаг лабораторной 3](WALKTHROUGH.md#лабораторная-3).

## Цель и задание

Создать документы с табличными частями, ограничить выбор номенклатуры по виду,
автоматически рассчитывать суммы строк и выводить итоги в подвалах таблиц.
Вызовы лабораторной 2 при старте должны быть закомментированы.

## Структура данных

Справочник **Поставщики** хранит поставщиков. У справочника **Договоры** владелец —
Поставщики, подчинение элементам. В шапках документов находятся Поставщик и Договор.

| Документ | Табличная часть | Поля строки |
| --- | --- | --- |
| ЗаказПоставщику | Материалы | Материал, Количество, Цена, Сумма |
| ЗаказПоставщику | Расходники | Расходник, Количество, Цена, Сумма |
| ПриходнаяНакладная | Материалы | Материал, Количество, Цена, Сумма |
| ПриходнаяНакладная | Расходники | Расходник, Количество, Цена, Сумма |
| РасходнаяНакладная | Товары | Товар, Количество, Цена, Сумма |
| РасходнаяНакладная | Услуги | Услуга, Сумма |

Материал, Расходник, Товар и Услуга ссылаются на один справочник
`СписокНоменклатуры`; различаются параметры выбора.

## Где и что настраивается

1. **Справочники → Договоры → Владельцы**: выберите Поставщики.
2. **Документы → нужный документ → Данные**: проверьте шапку и табличные части.
3. Выберите реквизит номенклатуры в табличной части, откройте свойства →
   **Параметры выбора → …**.
4. Имя параметра — `Filter.ВидНоменклатуры` (`Отбор.ВидНоменклатуры`).
   Тип значения — `EnumRef.ВидыНоменклатуры`, а не строка.
5. Задайте значение: Материал для материалов, РасходныйМатериал для расходников,
   Товар для товаров, Услуга для услуг.
6. **Документы → нужный документ → Формы → ФормаДокумента**.
   В среднем дереве элементов выберите поле количества, затем цены.
7. В свойствах каждого поля найдите **OnChange / ПриИзменении**.
   Создайте обработчик на клиенте. Он должен быть связан с полем:
   наличие процедуры в модуле без связи с событием недостаточно.

## Расчёт строки

Например, обработчик количества материалов получает текущую строку и пересчитывает её:

```bsl
&AtClient
Procedure МатериалыКоличествоOnChange(Item)
    CurrentRow = Items.Материалы.CurrentData;
    CurrentRow.Сумма = CurrentRow.Количество * CurrentRow.Цена;
    ПересчитатьИтоги();
EndProcedure
```

Такой же расчёт нужен при изменении цены. Для расходников используется
`Items.Расходники.CurrentData`, для товаров — `Items.Товары.CurrentData`.
Код размещается в **модуле формы**, не в модуле приложения.

## Запрет изменения суммы и итоги

1. В дереве элементов формы выберите колонку `МатериалыСумма`.
2. В свойствах установите **ReadOnly / ТолькоПросмотр**.
3. Повторите для расходников и товаров. Для `УслугиСумма` оставьте ввод доступным:
   в услугах нет количества и цены, сумма вводится вручную.
4. На вкладке **Реквизиты** редактора формы используются числовые реквизиты итогов:
   `ИтогМатериалы`, `ИтогРасходники` либо `ИтогТовары`, `ИтогУслуги`.
   Это реквизиты формы, не новые колонки табличной части документа.
5. У таблицы включается подвал, у колонки Сумма в **FooterDataPath** выбирается
   соответствующий реквизит итога.
6. Процедура `ПересчитатьИтоги` обходит строки объекта и складывает их суммы.
   Её вызывают обработчики количества, цены и суммы услуги.
7. В версиях Lab4–Lab6 добавлен вызов при открытии формы — итоги заполняются
   также при повторном открытии и вводе на основании.

Подвал отображает значение реквизита формы; сам по себе он не выполняет суммирование.

## Проверка и демонстрация

1. Запустите Предприятие, создайте поставщика и его договор.
2. Создайте заказ. Добавьте материал количеством 2 по цене 100 — сумма 200.
3. Добавьте вторую строку количеством 3 по цене 10 — сумма 30, итог материалов 230.
4. Измените количество первой строки на 4 — сумма 400, итог 430.
5. Попробуйте изменить рассчитанную сумму: поле должно быть только для просмотра.
6. Повторите расчёт для расходников и обеих таблиц приходной накладной.
7. В расходной накладной добавьте товар 2 × 100 и услугу с ручной суммой 500.
   Итог товаров 200, услуг 500 — это отдельные таблицы.
8. В каждом поле выбора проверьте ограничение по виду.
9. Запишите документы и откройте снова. Отдельно проверьте удаление строк:
   мгновенный пересчёт при удалении не подтверждён автоматическим сценарием.

## Что объяснить на защите

Документ фиксирует событие, табличная часть содержит несколько строк одного
документа. Событие ПриИзменении реагирует на ввод пользователя. Модуль формы
работает с элементами интерфейса, а реквизиты формы могут хранить промежуточные
итоги без добавления новых полей в базу.

Проверка конфигурации и связей обработчиков описана в [VALIDATION.md](../VALIDATION.md).
Она не заменяет проверку действий пользователя в формах.
