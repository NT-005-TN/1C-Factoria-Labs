# Запуск и подготовка лабораторных работ

[Все лабораторные](../README.md)

Проект «1С:Фактория» автоматизирует учебные процессы металлургического завода.
Работы выполняются последовательно: справочники → документы → движения → отчёт.
Источник заданий — [методичка](../materials/Методичка.docx).

## Какой файл выбрать

| Файл | Назначение |
| --- | --- |
| [Lab3-final.cf](../Lab3-final.cf) | Состояние после работы над лабораторной 3 |
| [Lab4.cf](../Lab4.cf) | Предыдущие объекты, ввод на основании и производство |
| [Lab5.cf](../Lab5.cf) | Всё из Lab4 и регистр продаж |
| [Lab6.cf](../Lab6.cf) | Итоговая накопительная конфигурация с отчётом |

Для демонстрации всех работ используйте **Lab6.cf**. `Lab1.cf` и `Lab2-progress.cf`
названы исторически: это архивные снимки, а не чистые версии после первой и второй
работ. Не загружайте их поверх итоговой конфигурации ради демонстрации ранних работ.

CF содержит структуру, формы и код, но не значения констант, сотрудников, товары
или документы пользователя. Резервная копия базы с данными имеет расширение DT.

## Загрузка в учебную базу

1. На GitHub откройте `Lab6.cf` и скачайте исходный файл кнопкой скачивания.
2. Запустите 1С, выберите учебную базу «Фактория» и нажмите **Конфигуратор**.
3. Сохраните резервную копию: **Администрирование → Выгрузить информационную базу**.
4. Если дерева объектов нет: **Конфигурация → Открыть конфигурацию**.
5. **Конфигурация → Загрузить конфигурацию из файла** → выберите скачанный CF.
6. **Конфигурация → Обновить конфигурацию базы данных** → подтвердите изменения.
7. **Отладка → Начать отладку** — откроется режим 1С:Предприятие.

Загрузка заменяет конфигурацию выбранной базы. Используйте отдельную учебную базу,
не рабочую базу организации. Платформа по методичке — 8.3.20 или новее;
проверки проекта выполнены на учебной 8.3.27.1606.

## Подготовка данных для показа

1. Создайте сотрудников и заполните общие данные организации.
2. Создайте хотя бы по одной позиции каждого вида: материал, расходный материал,
   товар и услуга. В каждой карточке обязательно выберите соответствующий вид.
3. Создайте поставщика и договор с этим поставщиком в качестве владельца.
4. Для проверки продаж используйте товар: количество 2, цена 100, сумма 200;
   услугу: сумма 500. Для единственной такой продажи итог равен 700.

Для первой работы дополнительно нужны не менее пяти сотрудников и группы
номенклатуры по рисунку методички. Эти данные нужно заполнить в своей базе.

## Где открывать код и свойства

- **Модуль приложения:** правой кнопкой на корне «Фактория» → открыть модуль управляемого приложения.
- **Общий модуль:** Общие → Общие модули → двойной щелчок по нужному модулю.
- **Модуль формы:** Документы → нужный документ → Формы → ФормаДокумента;
  внизу редактора выберите вкладку **Модуль**.
- **Модуль объекта:** правой кнопкой на документе → открыть модуль объекта.
- **Свойства элемента формы:** выберите элемент в среднем дереве редактора формы,
  затем откройте его свойства. Дерево конфигурации слева и дерево элементов формы — разные списки.

Часть свойств в этой конфигурации показывается по-английски:
`OnChange` = ПриИзменении, `OnOpen` = ПриОткрытии, `ReadOnly` = ТолькоПросмотр,
`DataPath` = ПутьКДанным, `FooterDataPath` = ПутьКДаннымПодвала,
`Filter` = Отбор, `CatalogRef` = СправочникСсылка, `EnumRef` = ПеречислениеСсылка.

## Что подтверждено проверками

Проверка конфигураций и обновление тестовой базы прошли успешно.
Для работ 4–6 выполнены отдельные автоматические сценарии:
[протокол](../validation/runtime-tests-2026-10-26.txt), [код тестов](../tests/LabTests.bsl).

Описанные сценарии демонстрации предназначены для проверки в пользовательской базе.

Инструкции «куда нажимать» описывают эквивалентный путь через интерфейс,
а не журнал выполненных вручную кликов. В этой доработке документации CF не изменяются.
