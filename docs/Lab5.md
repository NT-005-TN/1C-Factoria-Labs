# Лабораторная 5 — оборотный регистр продаж

[Все работы](../README.md) · [Запуск базы](START.md) · [Следующая работа](Lab6.md)

Пошаговое повторение с промежуточными действиями: [каждый шаг лабораторной 5](WALKTHROUGH.md#лабораторная-5).

## Цель и задание

Освоить регистр накопления и проведение документов. Расходная накладная должна
записывать продажи товаров и услуг в оборотный регистр, доступный в подсистеме Продажи.
Готовый снимок — [Lab5.cf](../Lab5.cf), также входит в Lab6.cf.

## Структура регистра

| Объект или поле | Настройка |
| --- | --- |
| Регистр Продажи | Регистр накопления, вид Обороты |
| Регистратор | РасходнаяНакладная |
| Измерение Номенклатура | СправочникСсылка.СписокНоменклатуры |
| Измерение Контрагент | СправочникСсылка.Поставщики |
| Ресурс Количество | Число 10,3 |
| Ресурс Сумма | Число 15,2 |
| Период записи | Дата расходной накладной |

Для измерений включены запрет незаполненных значений и использование в итогах.
Контрагент добавлен для группировки отчёта по рисунку лабораторной 6; в таблице
измерений задания 5 указан только реквизит Номенклатура. В текущей учебной модели
контрагент берётся из поля **Поставщик** расходной накладной — отдельного справочника
покупателей нет. Для суммы используется непосредственно число 15,2;
определяемый тип «ДенежныеСредства» методичка рекомендует, но не требует.

## Настройка в Конфигураторе

1. **Общие → Подсистемы → Продажи**: проверьте состав раздела.
2. **Регистры накопления → Продажи**: вид регистра **Обороты**.
3. На странице **Данные** проверьте измерения и ресурсы по таблице выше.
4. На странице **Подсистемы** отметьте Продажи.
5. Откройте **Документы → РасходнаяНакладная → Движения**.
6. Включите регистр Продажи. Документ также должен входить в подсистему Продажи.
7. Откройте **модуль объекта** расходной накладной, не модуль её формы.
8. Обработчик `Posting` (ОбработкаПроведения) создаёт движения.

## Как работает проведение

Обработчик включает запись набора движений регистра и очищает набор текущего
документа. Затем обходит табличные части:

| Источник | Номенклатура движения | Количество | Сумма |
| --- | --- | --- | --- |
| Строка Товары | Товар строки | Количество строки | Сумма строки |
| Строка Услуги | Услуга строки | Всегда 1 | Введённая сумма услуги |

Во всех движениях контрагент — Поставщик документа, период — его дата.
Очищается набор текущего регистратора, а не весь регистр продаж.
Перепроведение должно заменять движения документа, а не дописывать дубликаты.
При отмене проведения его записи удаляются платформой.

**Записать** сохраняет сам документ. **Провести** дополнительно формирует
учётные движения. Именно поэтому записанный, но непроведённый документ
не должен попадать в отчёт продаж.

## Проверка в Предприятии

1. **Продажи → Расходные накладные → Создать**.
2. Укажите поставщика, договор и дату.
3. В товарах добавьте позицию: количество 2, цена 100, сумма 200.
4. В услугах добавьте позицию с суммой 500.
5. Нажмите **Провести**.
6. Откройте движения документа либо список регистра Продажи. Отберите записи
   по этому регистратору, чтобы не спутать их с другими накладными.
7. Должны быть две записи: товар — количество 2, сумма 200;
   услуга — количество 1, сумма 500.
8. Общий результат данного документа: количество 3, сумма 700.
9. Проведите документ повторно: должно остаться две записи, не четыре.
10. Отмените проведение: записи этого регистратора должны исчезнуть.
11. Проведите снова перед демонстрацией отчёта лабораторной 6.

## Частые проблемы

- Нет движений: документ только записан, а не проведён, либо в нём нет строк.
- Ошибка пустого контрагента: заполните поле Поставщик.
- Неверная сумма: проверьте сохранённые суммы строк, а не только итог в подвале формы.
- В регистре больше двух записей: включите отбор по конкретному документу.

## Проверка и защита

Автоматический сценарий подтвердил движения товара и услуги, количество услуги 1,
отсутствие дублей после перепроведения и удаление движений при отмене.
[Протокол](../validation/runtime-tests-2026-10-26.txt) ·
[Проверка конфигурации](../validation/lab5-check.txt).

Покажите документ, две его записи регистра, повторное проведение и отмену.
Объясните, что измерения задают разрезы учёта, ресурсы — числовые показатели,
а регистратор связывает запись с документом. Оборотный регистр хранит обороты
за период, а не рассчитывает складские остатки.
