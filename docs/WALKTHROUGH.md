# Подробный порядок выполнения лабораторных 1–6

[На главную](../README.md) · [Подготовка и загрузка базы](START.md)

Это инструкция для повторения нашей конфигурации, включая промежуточные действия,
код и проверку. Она не является записью каждого исторического клика: работы 1–3
выполнялись пользователем с подсказками, работы 4–6 подготовлены через XML/BSL
и командный запуск Конфигуратора. Названия команд могут немного отличаться
в русской и английской локализации. Если объект уже существует, открывайте его,
а не создавайте второй с похожим именем.

## Перед началом

1. Запустите 1С и выберите **Фактория_Трухина**.
2. Нажмите **Конфигуратор**, а не Предприятие.
3. Выполните **Администрирование → Выгрузить информационную базу** и сохраните DT.
4. Откройте **Конфигурация → Открыть конфигурацию**.
5. Слева появится дерево объектов. Плюс рядом с узлом раскрывает содержимое;
   зелёный плюс панели добавляет новый объект в выбранный раздел.
6. Для изменения свойств выберите объект и используйте контекстное меню **Свойства**.
7. Двойной щелчок по справочнику или документу открывает окно его редактирования.
8. После каждого законченного блока сохраняйте изменения, выполняйте
   **Конфигурация → Обновить конфигурацию базы данных** и запускайте
   **Отладка → Начать отладку** для проверки.

Если задача — только открыть готовое решение, используйте [загрузку Lab6.cf](START.md).
Создавать все объекты заново после загрузки не нужно.

## Лабораторная 1

Подробности задания и ограничения: [описание работы 1](Lab1.md).

### Подсистема

1. Раскройте **Общие → Подсистемы**.
2. Выберите узел Подсистемы и нажмите зелёный плюс.
3. В имени укажите `Фактория`, в синониме — `Фактория`.
4. Закройте окно редактирования. Подсистема появится в дереве.
5. При создании следующих объектов открывайте их страницу **Подсистемы**
   и отмечайте Фактория. Это связывает объект с разделом интерфейса.

### Сотрудники

1. Выберите **Справочники**, нажмите плюс.
2. Имя — `Сотрудники`, синоним — `Сотрудники`.
3. Отметьте подсистему Фактория.
4. Перейдите на страницу **Данные**.
5. В списке реквизитов добавьте `Фамилия`.
6. В свойствах реквизита откройте выбор типа, выберите **Строка**, длина 50.
7. Аналогично добавьте `Имя` — строка 50.
8. Добавьте `Отчество` — строка 50.
9. Добавьте `ДатаРождения` — тип Дата, состав даты «Дата», без времени.
10. На странице Данные нажмите **Стандартные реквизиты**.
11. Выберите `Code` / Код. Справа в поле **Синоним** введите «Табельный номер».
12. Выберите `Description` / Наименование. Синоним — «Фамилия И.О.».
13. Подтвердите ввод переходом на другое поле, закройте список стандартных реквизитов.
14. Не создавайте отдельные пользовательские реквизиты вместо стандартного кода и наименования.

### Константы и единая форма

1. Выберите **Константы**, нажмите плюс.
2. Имя — `ГенеральныйДиректор`, синоним — «Генеральный директор».
3. В типе выберите `CatalogRef.Сотрудники` / СправочникСсылка.Сотрудники.
4. Отметьте подсистему Фактория.
5. Создайте константу `ИННОрганизация`, тип Строка, длина 12.
6. Создайте константу `ЮридическоеНаименование` со строковым типом.
7. Раскройте **Общие → Общие формы** и создайте форму `ДанныеОрганизации`.
8. В конструкторе формы выберите форму констант и включите все три константы.
9. Завершите конструктор. В реквизитах формы должен быть набор констант `ConstantsSet`.
10. У полей проверьте пути данных: `ConstantsSet.ГенеральныйДиректор`,
    `ConstantsSet.ИННОрганизация`, `ConstantsSet.ЮридическоеНаименование`.
11. В свойствах конфигурации проверьте назначение основной формы констант.
12. У отдельных констант отключите использование стандартных команд, чтобы
    не показывать пользователю лишние отдельные формы редактирования.
13. После обновления базы проверьте доступность общей формы и сохранение трёх значений.

### Перечисления

1. Выберите **Перечисления → Добавить**.
2. Имя — `ВидыНоменклатуры`, синоним — «Виды номенклатуры».
3. На странице Данные добавьте значения `Материал`, `РасходныйМатериал`, `Услуга`, `Товар`.
4. Для РасходныйМатериал задайте синоним с пробелом — «Расходный материал».
5. Создайте второе перечисление `ПроисхожденияНоменклатуры`.
6. Добавьте варианты импортного и отечественного происхождения.
7. Закройте редакторы перечислений.

### Номенклатура

1. Создайте справочник `СписокНоменклатуры`, синоним «Номенклатура».
2. На странице Иерархия включите иерархический справочник, вид — группы и элементы.
3. На странице Подсистемы отметьте Фактория.
4. На странице Данные откройте Стандартные реквизиты.
5. Код / Code: синоним «Артикул».
6. Наименование / Description: синоним «Название».
7. Родитель / Parent: синоним «Номенклатурная группа».
8. Закройте окно стандартных реквизитов.
9. Добавьте `ВидНоменклатуры`, тип `EnumRef.ВидыНоменклатуры`.
10. Добавьте `ПроисхождениеНоменклатуры`, тип `EnumRef.ПроисхожденияНоменклатуры`.
11. Обновите базу и откройте Предприятие.
12. В номенклатуре создайте группы и подгруппы по рисунку методички.
13. Через **Создать** добавьте позиции, задайте вид и происхождение каждой.
14. Создайте не менее пяти сотрудников. Заполните константы организации,
    выбрав генерального директора из списка сотрудников.

На ранних скриншотах обсуждался переключатель происхождения. В итоговой выгрузке
отдельной формы номенклатуры нет, поэтому выполненную настройку круглых
переключателей не утверждаем. Это отдельная проверка соответствия рисунку.

## Лабораторная 2

[Ожидаемые сообщения и все тестовые числа](Lab2.md).

### Модуль приложения

1. В дереве нажмите правой кнопкой на **Фактория**, то есть на самый верхний узел.
2. Выберите открытие модуля управляемого приложения.
3. Найдите процедуру `ПриНачалеРаботыСистемы` или создайте её, если отсутствует.
4. Создайте отдельную клиентскую процедуру `ВыполнитьЗадания21_23`.
5. Внутри последовательно разместите задания 2.1, 2.2, 2.3.
6. Используйте [полный сохранённый модуль](../source/Lab6/Ext/ManagedApplicationModule.bsl):
   на GitHub нажмите **Raw**, чтобы видеть код без разметки.
7. Не копируйте обрамляющие Markdown-строки с тройными обратными кавычками в редактор 1С.
8. Не добавляйте второй обработчик с уже существующим именем.

### Последовательность трёх алгоритмов

1. Задайте ФИО строкой из фамилии, имени и отчества.
2. Разделите строку `СтрРазделить(ФИО, " ")`.
3. Возьмите фамилию из элемента 0 и первые буквы элементов 1 и 2 через `Лев`.
4. Добавьте точки после инициалов, выведите полное и краткое ФИО через `Сообщить`.
5. Задайте себестоимость 100, наценку 40 и ставку НДС 20.
6. Рассчитайте цену с наценкой, затем цену с НДС. Результат — 168.
7. Задайте загаданное число 500 и выбранное 495.
8. Сначала проверьте выход загаданного числа за 0–1000.
9. Затем проверьте попадание выбранного в интервал от загаданного минус 10
   до загаданного плюс 10 включительно.
10. В каждую ветку добавьте нужное сообщение. Пустая ветка победы второго игрока
    не выводит результат — именно это было видно в одном из промежуточных вариантов.
11. Не используйте прежние вызовы `Модуль(...)` и `Abs(...)`: на скриншотах они
    вызывали ошибку «Процедура или функция с указанным именем не определена».

### Общие модули

1. Раскройте **Общие → Общие модули**.
2. Создайте `УКЗ_Клиент`. В свойствах включите клиент управляемого приложения.
3. В его модуле разместите экспортную процедуру `СформироватьМассив` из
   [исходника](../source/Lab6/CommonModules/УКЗ_Клиент/Ext/Module.bsl).
4. Она создаёт массив фамилий, переносит в список значений, сортирует и выводит.
5. Создайте `УКЗ_ВызовСервера`. Включите Сервер и Вызов сервера.
6. Разместите экспортную процедуру `СформироватьТаблицуЗначений` из
   [исходника](../source/Lab6/CommonModules/УКЗ_ВызовСервера/Ext/Module.bsl).
7. Таблица содержит Яблоки 10, Яблоки 20, Груши 5. После `Свернуть` — Яблоки 30, Груши 5.
8. Вернитесь в модуль приложения. В начале работы системы вызовите все три процедуры:

```bsl
ВыполнитьЗадания21_23();
УКЗ_Клиент.СформироватьМассив();
УКЗ_ВызовСервера.СформироватьТаблицуЗначений();
```

9. Обновите базу, перезапустите Предприятие и прочитайте сообщения.
10. Проверьте варианты игры из таблицы в описании Lab2.
11. После показа поставьте `//` перед тремя вызовами. Код самих процедур оставьте.

В сохранённой версии нет обратного переноса отсортированного списка в новый массив.
Это отмеченное отличие от буквального требования задания, а не выполненный шаг.

## Лабораторная 3

[Состав документов и сценарий проверки](Lab3.md).

### Поставщики и договоры

1. В Справочниках добавьте `Поставщики` и включите в Факторию.
2. Добавьте справочник `Договоры`, также включите в Факторию.
3. Дважды откройте Договоры, выберите страницу **Владельцы**.
4. Нажмите кнопку редактирования списка владельцев, отметьте Поставщики.
5. Внизу выберите подчинение **Элементам**.
6. Сохраните. Это задаёт владельца договора, но само по себе не заменяет настройку
   отбора договоров в конкретном поле формы.

### Заказ поставщику и его реквизиты

1. Выберите Документы → Добавить.
2. Имя — `ЗаказПоставщику`, синоним — «Заказ поставщику».
3. На странице Подсистемы отметьте Фактория.
4. На странице Данные в верхнем списке реквизитов добавьте `Поставщик`.
5. Его тип — `CatalogRef.Поставщики`.
6. Добавьте `Договор`, тип `CatalogRef.Договоры`.
7. В списке табличных частей добавьте `Материалы`.
8. Внутри Материалы добавьте `Материал`, тип `CatalogRef.СписокНоменклатуры`.
9. Добавьте числовые реквизиты `Количество`, `Цена`, `Сумма`.
10. Создайте табличную часть `Расходники`.
11. Внутри добавьте `Расходник` того же ссылочного типа и числовые `Количество`, `Цена`, `Сумма`.
12. Не добавляйте Количество в шапку: оно должно находиться внутри каждой таблицы.

### Отбор номенклатуры

1. В дереве слева раскройте ЗаказПоставщику → Табличные части → Материалы.
2. Выберите реквизит Материал, откройте свойства.
3. Найдите **Параметры выбора**, нажмите `…`.
4. В окне параметров нажмите зелёный плюс.
5. В колонке Имя введите `Filter.ВидНоменклатуры`.
6. В колонке Значение откройте выбор типа кнопкой `T`, если она показана.
7. Выберите `EnumRef.ВидыНоменклатуры`, нажмите ОК.
8. Выберите значение перечисления **Материал**, а не строку с таким текстом.
9. Нажмите ОК в окне параметров.
10. Повторите для Расходник, но значение выберите **РасходныйМатериал**.

### Остальные документы

1. Создайте `ПриходнаяНакладная`, синоним «Приходная накладная».
2. Добавьте шапку Поставщик и Договор, таблицы Материалы и Расходники по образцу заказа.
3. Настройте оба отбора так же, как у заказа.
4. Создайте `РасходнаяНакладная`, синоним «Расходная накладная».
5. Добавьте Поставщик и Договор.
6. Добавьте таблицу `Товары`: Товар, Количество, Цена, Сумма.
7. У Товар тип — ссылка на СписокНоменклатуры; параметр выбора — вид Товар.
8. Добавьте таблицу `Услуги`: Услуга и Сумма. Количество и Цена здесь не нужны.
9. У Услуга тип — ссылка на СписокНоменклатуры; параметр выбора — вид Услуга.
10. Все три документа включите в Факторию.

### Создание формы документа

1. Раскройте документ в дереве слева.
2. Выберите вложенный узел **Формы**, нажмите плюс.
3. В конструкторе выберите **Форма документа**, имя `ФормаДокумента`.
4. Включите номер, дату, реквизиты шапки и обе таблицы с их колонками.
5. Завершите конструктор. Откроется редактор формы.
6. Слева внутри редактора находятся **Элементы**, справа — **Реквизиты**,
   снизу — предварительный вид формы.
7. Вкладки **Форма** и **Модуль** находятся у нижнего края именно этого редактора.
8. Если окно слишком маленькое, разверните его кнопкой в его заголовке.
9. Не удаляйте форму, чтобы просто изменить код. Открывайте вкладку Модуль.
10. Если удаление запрещено из-за ссылок, это не ошибка кода: форму использует
    другой объект или настройка. Для наших расчётов удалять её не нужно.

### События количества и цены

1. В дереве элементов формы раскройте таблицу Материалы.
2. Выберите `МатериалыКоличество`, а не одноимённый реквизит в дереве конфигурации.
3. В свойствах справа прокрутите до раздела **События**.
4. Найдите **OnChange / ПриИзменении**.
5. Нажмите кнопку создания обработчика рядом с полем события.
6. Выберите **Создать на клиенте**, нажмите ОК.
7. В открывшейся процедуре замените комментарий-заглушку кодом расчёта строки:

```bsl
CurrentRow = Items.Материалы.CurrentData;
CurrentRow.Сумма = CurrentRow.Количество * CurrentRow.Цена;
ПересчитатьИтоги();
```

8. Процедуру ПересчитатьИтоги добавьте следующим блоком, иначе проверка сообщит,
   что её имя не определено.
9. Вернитесь на вкладку Форма, создайте OnChange для `МатериалыЦена` с тем же телом.
10. Создайте OnChange для `РасходникиКоличество` и `РасходникиЦена`.
    В них используйте `Items.Расходники.CurrentData`.
11. Повторите четыре привязки в форме ПриходнаяНакладная.
12. В РасходнаяНакладная создайте два обработчика: `ТоварыКоличествоOnChange`
    и `ТоварыЦенаOnChange`, текущая строка — `Items.Товары.CurrentData`.
13. Для `УслугиСумма` создайте OnChange с единственной строкой `ПересчитатьИтоги();`.

### Сумма в подвале — создание реквизитов формы

1. Откройте форму ЗаказПоставщику, вкладку **Форма**.
2. Справа в редакторе нажмите вкладку **Реквизиты**. Это не раздел
   «Реквизиты» документа в самом левом дереве.
3. Добавьте реквизит формы кнопкой плюс.
4. Имя — `ИтогМатериалы`, тип **Число**; для денежного итога задайте точность 2.
5. Добавьте второй реквизит — `ИтогРасходники`, также числовой.
6. Оба реквизита должны быть самостоятельными реквизитами формы рядом с Object,
   а не полями внутри Object.Материалы.
7. Перетаскивать их в форму как отдельные поля ввода не требуется.

### Сумма в подвале — привязка колонок

1. В среднем дереве **Элементы** выберите таблицу **Материалы** с иконкой таблицы.
2. В свойствах найдите **Подвал / Footer** и включите.
3. Раскройте таблицу, выберите колонку **МатериалыСумма**.
4. В свойствах найдите **FooterDataPath / ПутьКДаннымПодвала**.
5. Нажмите `…` и выберите **ИтогМатериалы**.
6. Не меняйте обычный `DataPath`: он должен оставаться путём к сумме строки.
7. Если в FooterText написать «Итого», появится только текст — это не расчёт числа.
8. Выберите таблицу Расходники, включите её подвал.
9. У колонки РасходникиСумма задайте FooterDataPath = ИтогРасходники.
10. У обеих колонок Сумма включите **ReadOnly / ТолькоПросмотр**.

### Сумма в подвале — полный пересчёт

1. Внизу редактора формы нажмите **Модуль**.
2. После последнего EndProcedure добавьте одну процедуру:

```bsl
&AtClient
Procedure ПересчитатьИтоги()
    ИтогМатериалы = 0;
    For Each CurrentRow In Object.Материалы Do
        ИтогМатериалы = ИтогМатериалы + CurrentRow.Сумма;
    EndDo;

    ИтогРасходники = 0;
    For Each CurrentRow In Object.Расходники Do
        ИтогРасходники = ИтогРасходники + CurrentRow.Сумма;
    EndDo;
EndProcedure
```

3. Начальное присваивание нуля обязательно: иначе старый итог прибавлялся бы снова.
4. Проверьте, что во всех четырёх OnChange вызов пересчёта стоит **после** вычисления суммы строки.
5. Повторите реквизиты, подвалы и процедуру в форме ПриходнаяНакладная.
6. В расходной форме создайте реквизиты `ИтогТовары` и `ИтогУслуги`.
7. Свяжите подвал ТоварыСумма с ИтогТовары, УслугиСумма — с ИтогУслуги.
8. У ТоварыСумма включите ReadOnly, у УслугиСумма оставьте выключенным.
9. В модуле расходной формы используйте:

```bsl
&AtClient
Procedure ПересчитатьИтоги()
    ИтогТовары = 0;
    For Each CurrentRow In Object.Товары Do
        ИтогТовары = ИтогТовары + CurrentRow.Сумма;
    EndDo;
    ИтогУслуги = 0;
    For Each CurrentRow In Object.Услуги Do
        ИтогУслуги = ИтогУслуги + CurrentRow.Сумма;
    EndDo;
EndProcedure
```

### Пересчёт при открытии

1. Вернитесь на вкладку Форма.

6. Свяжите событие с этой процедурой во всех трёх формах.

   Не считать наличие OnChange количества обработчиком удаления.

```bsl
Procedure Posting(Cancel, Mode)
    RegisterRecords.Продажи.Write = True;
    RegisterRecords.Продажи.Clear();
    For Each Row In Товары Do
        Movement = RegisterRecords.Продажи.Add();
```
