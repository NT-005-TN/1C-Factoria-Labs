# Лабораторная 4 — ввод на основании и производство

Пошаговое повторение с промежуточными действиями: [каждый шаг лабораторной 4](WALKTHROUGH.md#лабораторная-4).

## Цель и задание

Научиться переносить данные между документами и задавать отбор по нескольким
значениям. Требуется ввод приходной накладной на основании заказа, документ
производства и выбор двух видов номенклатуры для производственных материалов.
В методичке заголовок работы — №4, но задания внутри обозначены 5.1–5.3.

Готовый снимок — [Lab4.cf](../Lab4.cf); все изменения также есть в Lab6.cf.

## Приходная накладная на основании заказа

1. В Конфигураторе откройте **Документы → ПриходнаяНакладная**.
2. На странице **Ввод на основании** укажите документ ЗаказПоставщику.
3. Откройте модуль объекта приходной накладной через контекстное меню документа.
4. Обработчик `Filling` (ОбработкаЗаполнения) проверяет тип основания.
5. Для заказа отключает стандартное заполнение и переносит шапку и обе таблицы.

Основные операции обработчика:

```bsl
Поставщик = FillingData.Поставщик;
Договор = FillingData.Договор;
Материалы.Load(FillingData.Материалы.Unload());
Расходники.Load(FillingData.Расходники.Unload());
```

`Unload` выгружает строки в таблицу значений, `Load` загружает в табличную часть
приходной накладной. Переносятся не только ссылки на позиции, но и количество,
цена и сумма. Полный обработчик с проверкой типа находится в
[модуле объекта](../source/Lab4/Documents/ПриходнаяНакладная/Ext/ObjectModule.bsl).

## Документ производства

1. **Общие → Подсистемы**: создайте или откройте Производство.
2. **Документы → ПроизводствоПродукции**: синоним «Производство продукции».
3. На странице **Подсистемы** отметьте Производство.
4. На странице **Данные** используются две табличные части:

| Табличная часть | Реквизит | Тип |
| --- | --- | --- |
| Материалы | Номенклатура | СправочникСсылка.СписокНоменклатуры |
| Материалы | Количество | Число 10,3 |
| Товары | Номенклатура | СправочникСсылка.СписокНоменклатуры |
| Товары | Количество | Число 10,3 |

5. Для `Материалы.Номенклатура` откройте свойства → **Параметры выбора**.
6. Имя — `Filter.ВидНоменклатуры`; значение имеет тип **FixedArray / ФиксированныйМассив**.
7. В массив включены значения перечисления Материал и РасходныйМатериал.
   Это два значения перечисления, а не одна строка с перечислением через запятую.
8. Для `Товары.Номенклатура` задайте один вид — Товар.
9. Обновите базу. Форма документа строится платформой автоматически.

Документ фиксирует использованные материалы и выпущенные товары. Движения
складских остатков и расчёт себестоимости в этой работе не реализуются.

## Проверка ввода на основании

1. В Предприятии: **Фактория → Заказы поставщику → Создать**.
2. Выберите поставщика и договор.
3. Материалы: одна строка 2 × 100 = 200.
4. Расходники: одна строка 3 × 10 = 30.
5. Нажмите **Записать**, затем **Создать на основании → Приходная накладная**.
   Если кнопки нет на панели, проверьте меню **Ещё**.
6. Проверьте поставщика, договор, обе строки, количество, цену и суммы.
7. Запишите новую накладную. Заказ должен остаться самостоятельным документом.

## Проверка производства

1. **Производство → Производство продукции → Создать**.
2. В материалах попробуйте выбрать материал, затем расходный материал: оба вида доступны.
3. Услуга и товар не должны попадать в этот отбор.
4. В товарах выберите позицию вида Товар.
5. Укажите дробное количество материала 1,500, запишите и откройте документ снова.
6. Покажите, что дробная часть сохраняется.

## Проверено и что показать на защите

Автоматически проверены перенос шапки и обеих таблиц, наличие двух значений
в фиксированном массиве и запись количества 1,5. Проверка модулей и обновление
базы прошли успешно: [проверка Lab4](../validation/lab4-check.txt),
[сценарии](../validation/runtime-tests-2026-10-26.txt).

На защите покажите исходный заказ, созданный приход, документ производства
и настройку массива. Объясните: ввод на основании сокращает повторный ввод,
а фиксированный массив позволяет одним параметром выбора разрешить несколько видов.
