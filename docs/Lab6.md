# Лабораторная 6 — отчёт по продажам на СКД

[Все работы](../README.md) · [Запуск базы](START.md) · [Предыдущая работа](Lab5.md)

## Цель и задание

Создать отчёт средствами Системы компоновки данных: получить обороты продаж,
настроить период и необязательный отбор по номенклатуре, вывести количество,
сумму и общие итоги. Отчёт доступен в подсистеме Продажи.
Итоговая конфигурация — [Lab6.cf](../Lab6.cf).

## Объекты и источник данных

- Отчёт `ОтчетПоПродажам`, синоним «Отчёт по продажам».
- Макет `ОсновнаяСхемаКомпоновкиДанных` типа «Схема компоновки данных».
- Источник — виртуальная таблица `РегистрНакопления.Продажи.Обороты`.
- Поля — Номенклатура, Контрагент, Количество, Сумма.
- Ресурсы СКД — суммы по Количество и Сумма.

Отчёт читает движения регистра, а не напрямую строки документов.
Предварительно выполните сценарий проведения из [лабораторной 5](Lab5.md).

## Настройка схемы

1. В Конфигураторе откройте **Отчёты → ОтчетПоПродажам**.
2. На странице **Подсистемы** проверьте Продажи.
3. Откройте **Основная схема компоновки данных**.
4. На вкладке **Наборы данных** используется набор данных типа «Запрос».
5. Запрос получает обороты и применяет необязательный отбор:

```bsl
ВЫБРАТЬ
    ПродажиОбороты.Номенклатура КАК Номенклатура,
    ПродажиОбороты.Контрагент КАК Контрагент,
    ПродажиОбороты.КоличествоОборот КАК Количество,
    ПродажиОбороты.СуммаОборот КАК Сумма
ИЗ
    РегистрНакопления.Продажи.Обороты(
        &НачалоПериода, &КонецПериода, , ) КАК ПродажиОбороты
ГДЕ
    (&Номенклатура = ЗНАЧЕНИЕ(Справочник.СписокНоменклатуры.ПустаяСсылка)
     ИЛИ ПродажиОбороты.Номенклатура = &Номенклатура)
```

6. Заголовки задаются в свойствах полей набора данных. Псевдонимы запроса
   не переименовываются ради оформления заголовков.
7. На вкладке **Ресурсы**: `Количество` → `Сумма(Количество)`;
   `Сумма` → `Сумма(Сумма)`.

## Параметры

| Параметр | Назначение |
| --- | --- |
| Период | СтандартныйПериод, по умолчанию текущий месяц |
| НачалоПериода | Дата, выражение `&Период.StartDate` |
| КонецПериода | Дата, выражение `EndOfPeriod(&Период.EndDate, "Day")` |
| Номенклатура | Ссылка на СписокНоменклатуры; пустая ссылка означает все позиции |

Конец дня включает продажи последнего дня периода, а не только момент 00:00.
Период и Номенклатура включены в пользовательские настройки варианта.
Необязательность выбора номенклатуры обеспечивается пустым значением и условием
запроса: пустой параметр не должен отсеивать все строки.

## Группировки и оформление

1. На вкладке **Настройки** используется группировка Номенклатура.
2. Внутри неё — Контрагент, как на рисунке задания.
3. Выбранные поля: Номенклатура, Контрагент, Количество, Сумма.
4. Общие итоги располагаются в конце по вертикали.
5. Макет оформления — **Море**.

Контрагент — дополнительное измерение регистра из лабораторной 5. Оно
заполняется из существующего поля Поставщик расходной накладной.
Отдельного макета печатной формы нет: макет ОсновнаяСхемаКомпоновкиДанных
хранит описание СКД, а результат строится автоматически.

## Как сформировать и показать

1. В Предприятии откройте **Продажи → Отчёт по продажам**.
2. Нажмите **Настройки**. Выберите период, включающий дату проведённой накладной.
3. Поле Номенклатура сначала оставьте пустым.
4. Нажмите **Сформировать**.
5. Для единственной тестовой продажи из работы 5 должны быть товар на 200
   и услуга на 500. Общие итоги: количество 3, сумма 700.
6. Если есть другие продажи за этот период, итоги будут учитывать и их.
7. В настройке Номенклатура выберите только тестовый товар, сформируйте повторно.
   Для него ожидается количество 2 и сумма 200.
8. Отмените проведение тестовой накладной и сформируйте отчёт заново —
   её продажи должны исчезнуть. Затем восстановите проведение.

## Если отчёт пустой

Проверьте последовательно: документ проведён; в регистре есть движения;
дата входит в период; не выбран другой товар; после изменения параметров нажата
кнопка Сформировать. Загрузка CF сама по себе не создаёт продажи.

## Проверка результата

Автоматически выполнены запрос, компоновка и вывод в табличный документ в памяти.
При периоде и отборе по тестовому товару найдена сумма 200.
Проверены пользовательские идентификаторы параметров.
[Протокол](../validation/runtime-tests-2026-10-26.txt) ·
[Проверка конфигурации](../validation/lab6-check.txt).

Внешний вид окна вручную не проверялся. В использованной учебной платформе
экспорт табличного документа был запрещён лицензией; отчёт следует показывать
непосредственно в окне 1С, а не рассчитывать на сохранение в Excel или HTML.

## Что объяснить на защите

СКД объединяет источник данных, параметры, ресурсы и настройки представления.
Виртуальная таблица Обороты даёт агрегированные движения за период.
Группировка организует строки, ресурс определяет вычисление итогов,
пользовательские параметры позволяют менять выборку без редактирования запроса.
